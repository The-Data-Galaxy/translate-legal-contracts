# 法律表达规则

## 保留法律效果

| 维度 | 复核要点 |
| --- | --- |
| 主体 | 谁承担义务、享有权利、作出保证；包括主体范围、关联方与代表人 |
| 行为 | 应做、不得做、可选择做，还是仅有事实陈述 |
| 强度 | 结果义务、合理努力、商业上合理努力、尽最大努力等不得互换 |
| 条件 | 生效条件、先决条件、通知、审批及前置程序 |
| 时间 | 起算点、截止日、工作日与自然日、期间是否含首尾日 |
| 范围 | 全部或部分、直接或间接、已知或应知、实际发生或可合理预见 |
| 例外 | unless、except、provided that、subject to等的修饰对象和层次 |
| 救济 | 解除、终止、撤销、赔偿、补偿、返还、继续履行的区别 |
| 金额 | 币种、含税与否、上限、比例、基数、累计或单次、支付路径 |
| 责任 | 过错、因果关系、免责、责任上限及其例外、第三方索赔 |

## 定义词与当事人

- 建立术语表，包含定义词、主体名称、角色、文件名称和高风险术语。遵循用户提供的正式译名；没有依据时保留名称或标明待确认，不臆造工商登记英文名。
- 区分被定义的Agreement与一般agreement；统一大小写、单复数及所有格。并非所有中文名词都需要定义或首字母大写。
- 按交易角色使用Buyer、Supplier、Customer、Agent等称谓。甲乙方与角色存在歧义时先核实，不自动把乙方译为Supplier。
- 确认“本合同”“该协议”“补充协议”“订单”的指代。英文引用指向真实存在的条款、附件或定义。
- 保留用户已有的文件名称；未经授权不把框架协议、订单或承诺书改为另一法律文件类型。

## 英文合同表达

- 用具体主体和主动语态组织义务；可以调整语序和分句，必须保留逻辑与范围。
- 采用一致的义务表达体系。shall/must表达义务时保持一致；may表达许可或裁量。不要机械把“应”全部译为shall或把“可以”全部译为can。
- 区分“应当”“有权”“同意”“确认”“承诺”“保证”。representations、warranties和covenants可能产生不同法律效果，不无依据增加术语组合。
- “包括”是否开放列举以原文为准，不习惯性添加including without limitation。
- “赔偿”不必然是indemnify；“违约金”不一律是penalty；“连带责任”不简单写成joint liability；“解除”不一律是rescind。按法律效果和法域判断，无法确认时记录问题。
- 对“合理”“及时”“必要”不补数值；对“协商一致”不增加书面形式要求，除非其他条款已有依据。
- 不加入原文没有的entire agreement、time is of the essence、exclusive remedy等条款或效果。
- 翻译不得作为提升某一方谈判地位的隐形修订。用户授权优化时，另作可识别的修改或建议。

## 数字、日期与商业条件

- 金额、比例和数量逐项保留来源；对十万、万元、亿等换算独立重算。币种不明确时不自选币种。
- 对佣金、折扣、返利、违约金检查基数：订单金额、实收金额、净收入、含税金额不能混用。
- 日期采用无歧义表达；不把11/12自行认定为某一种日期制式。
- 对“月末后30日”“收到发票后30个工作日”等保留起算事件和期间类型。
- 保留空白、勾选状态和变量，不生成假数字、姓名、账户或签字。

## 原文问题与法域

- 原文矛盾、定义缺失、引用断裂和称谓不一致，忠实翻译并单列问题，不悄悄补为双方约定。
- 未指定适用法时，不将中国法概念自动替换为英美法概念，不新增适用法或争议解决地。
- 用户要求按某法域重拟合同时另行核验法律，区分忠实译文与当地法修改。
- 需要研究现行法律或官方措辞时，核对官方法规、监管机构、法院或政府发布的双语文本并保留来源；不编造官方译法。

## 场景对应

| 请求 | 应完成的工作 |
| --- | --- |
| 做成双语版，注意准确 | 逐条对照、保留结构，完成法律含义和排版核查 |
| 不仅翻译，要符合英文合同习惯 | 调整英文表达和语序，保留交易条件与权利义务 |
| 目录没译、英文漏编号 | 同步修复目录和正文，核验自动编号，重新渲染 |
| 隐去某行业表述 | 按指定范围一致处理中文、英文、定义和附件 |
| 英文合同改中文对照 | 准确翻译中文，按要求将英文原文设为11 pt，检查重排 |
